# 課堂活動建議：用 GAMELIFE 認識一份工作的一天

適用：國中到大學的職涯探索、生涯規劃、綜合活動課。只需要能上網的手機或電腦，免註冊、免安裝。

> **先講清楚**：遊戲裡的人物、事件和數字大多是虛構的情境；各類工作的時間比例取自公開資料或推估，畫面上都有註明來源。結算卡描述的是玩家當天做選擇的節奏和偏好，**不是職業測驗**，不會告訴學生「適合」什麼工作。也不能拿來當作任何職業的實務訓練。

## 一堂課的流程（45～50 分鐘）
| 時間 | 活動 | 說明 |
|---|---|---|
| 5 分鐘 | 暖身 | 問全班：「你覺得一位軟體工程師一天中，花最多時間在做什麼？寫程式大概佔幾成？」先不公布答案。 |
| 15 分鐘 | 玩一天 | 每人或兩人一組。遊戲第一步會請大家先猜時間分配，請學生**認真猜**，這是之後討論的素材。 |
| 5 分鐘 | 看對照 | 遊戲會比較「你猜的」和「實際資料」。請學生記下落差最大的一類。 |
| 15 分鐘 | 分組討論 | 3～4 人一組，用下面的討論題。 |
| 5～10 分鐘 | 全班分享 | 每組分享一個「沒想到」的發現。 |

### 兩堂課版本（同一份工作、不同選擇）
目前遊戲只有軟體工程師一份工作。第二堂請學生按結算畫面的「再玩一次」，**刻意選第一次沒選的回應**（例如第一次逐行 review，這次只看重點就核准；第一次答應加班趕出新需求，這次說明要另開 ticket），再比較兩張結算卡：**換了選擇，這一天的結果和壓力來源差多少？** 哪些代價是當下就出現，哪些到下午才出現？

### 分組對照版本
同一組裡，兩人用不同策略各玩一次（一人「能幫就幫、有求必應」，一人「先顧好自己的 ticket」），再交換各自遇到的「打斷」和「來不及」的事。討論：同一天、同樣的事件，為什麼兩人最後的精力、時間和信任差這麼多？現實中一位工程師會怎麼在兩者之間取捨？

## 討論題（挑 2～3 題）
1. 你猜的時間分配和實際資料，落差最大的是哪一類？你為什麼會那樣猜？
2. 今天哪一個選擇最難？你放棄了什麼（時間、精力或別人的信任）？
3. 有沒有哪件事是「早上省下的時間，下午要還」？現實工作中有類似的例子嗎？
4. 遊戲裡的「打斷」（來電、有人走過來）對你的計畫造成什麼影響？
5. 你在遊戲裡學到了哪個新名詞？它讓你對這份工作的印象有什麼改變？
6. 如果要更了解這份工作，你會去問誰、問什麼問題？

## 帶領時的提醒
- 每個選項都有代價，**沒有標準答案**。請避免用「選對、選錯」評價學生的選擇。
- 結算卡上的描述（例如節奏、互動偏好）只反映這一局的選擇，換一天、換一組選擇都可能不同。
- 學生可以在畫面上點有虛線的名詞看解釋；首頁的「名詞圖鑑與資料來源」列出了所有資料出處。
- 遊戲不會上傳任何資料；名字欄是選填，只存在學生自己的裝置上。

## 延伸作業（選用）
- 訪問一位從事該工作的家人或朋友，問他：「你一天中最花時間的是什麼？和遊戲裡的比例像嗎？」
- 寫一段 100 字：「我原本以為○○的工作是……，玩完之後發現……。」
