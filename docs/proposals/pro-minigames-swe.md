# 提案：軟體工程師專業小遊戲（已核准（HP7），已實作 v0.9；HP8／HP9 後續已實作 v0.10）

待辦 #6。已決定的規則：
- 小遊戲嵌進既有事件，不新增事件。
- 只在有倒數的時段扣時間，規則和查資料一樣（每張卡 5 分鐘）。
- 時間分配不新增類別。
- 內容先上線，並標示「待審查」。

## 機制：沿用「查資料」，換外觀
引擎不另做新的判定邏輯，三種小遊戲都是「打開卡片，找齊有關的卡，才出現選項」。差別在 `investigate.kind`：

| kind | 外觀 | 卡片代表 |
|---|---|---|
| `info`（預設，現有） | 資料卡 | 文件、紀錄 |
| `review` | 等寬字的程式碼行，含行號 | 一行改動 |
| `debug` | 終端機風格（深底），分「錯誤訊息／程式碼／環境」三種標籤 | 一條線索 |
| `test` | 勾選清單 | 一個測試情況 |

- **翻開卡片後**：顯示一句白話說明，解釋這行或這條線索為什麼有關、為什麼無關。這是本次的學習重點。
- **完成後**：多一行「小知識」，用一句話說明這項工作在真實職場的樣子。
- **待審查標示**：面板右上角顯示「內容待從業者審查」小徽章，由 `investigate.reviewPending: true` 控制。

選項與代價維持原樣，小遊戲不計分，也不會判定答對或答錯，維持「沒有明顯正解」的原則。

## 三個小遊戲的內容（草稿）

### 1. Code review：「一個很大的 PR」（s-review，上午時段，有倒數）
題目：「看這段改動，點出可能有問題的行」

```
1  function 計算總價(購物車) {
2    let 總價 = 0
3    for (i = 1; i < 購物車.長度; i++)
4      總價 += 購物車[i].價格 × 購物車[i].數量
5    if (折扣碼 = "VIP") 總價 = 總價 × 0.9
6    return 總價
```
- **有關：第 3 行**。清單從第 0 個開始數，從 1 開始會漏掉第一件商品。
- **有關：第 5 行**。「=」是把值放進去，不是比較，所以每個人都會拿到 VIP 折扣。
- **無關：第 2、4、6 行**。各附一句說明為什麼沒問題，例如「總價從 0 開始累加，正常」。
- **小知識**：review 時通常一次只看一小段改動，改動太大就容易漏看，所以團隊常要求拆成小 PR。

### 2. Debug：「終於可以寫程式」（s-deepwork，沒有倒數，不扣時間）
題目：「測試失敗了，找出原因的線索」
- **有關：錯誤訊息**。預期「10/23 00:30」，實際是「10/22 16:30」，剛好差 8 小時。
- **有關：程式碼**。訂單時間用世界標準時間（UTC）存。
- **有關：程式碼**。畫面上顯示時間時，沒有轉成台灣時間（UTC+8）。
- **無關：環境**。套件版本和昨天一樣。
- **無關：環境**。這台電腦上的其他測試都通過。
- **無關：程式碼**。按鈕的顏色設定。
- **小知識**：除錯常是先從「差了多少」看出模式，例如剛好 8 小時，就提示可能是時區問題。

這和事件現有的結果文字「一個時區轉換的錯誤」相互對應。

### 3. 單元測試：「測試環境出錯」（s-bug-found，傍晚時段，有倒數；只在上午快速核准 PR 時才出現）
在事件內文最後加一句：「修好之前，先寫測試重現問題」。
題目：「這個計算總價的功能，要測哪些情況？」
- **有關**：購物車只有一件商品。這正好能抓到第 3 行漏算第一件的錯。
- **有關**：沒有輸入折扣碼。這能抓到第 5 行每個人都有折扣的錯。
- **有關**：空的購物車。總價應該是 0，不應該當掉。
- **無關**：按鈕顏色好不好看。這是設計審查，不是單元測試。
- **無關**：測試要在哪間會議室跑。和程式無關。
- **小知識**：單元測試是用小例子檢查一個函式。發現錯誤後先補一個會失敗的測試，修好後它就會保護以後不再犯同樣的錯。

### 4. 修印表機：打斷事件（新的 i-s-printer，發生在「等待 CI」s-ci 期間）
- 來電者是行政同事，在座位旁：「你是工程師吧？印表機一直卡紙，可以幫看一下嗎？」
- 選項一「幫忙看看」：時間 −10、信任 +10。結果：「原來是紙放反了。行政很感謝你，但 CI 早就跑完了。」
- 選項二「請他找 IT 報修」：信任 −5。結果：「你回到螢幕前，他走去報修，背影有點落寞。」
- 這反映很多工程師都遇過的現象：別人以為寫程式的人什麼電腦問題都會修。

## 需要配合調整的地方
- **詞彙表**：加入「單元測試」「除錯」「UTC」「時區」。名詞必須出現在內文裡，驗證器會檢查。
- **倒數時間**：
  - review 至少多 10 分鐘，可能要把上午時段的 30 分鐘拉長。
  - 單元測試至少多 15 分鐘，可能要把傍晚時段的 50 分鐘拉長。
  - 調整後必須通過驗證器的「做得完、但有壓力」檢查，實際數字由實作時算出來，再給你看。
- **驗證器**：
  - 每張卡加上 `why`（白話說明），完成後的小知識放在 `tip`。
  - `kind` 必須是上面四種之一。
  - 打斷事件的數量上限要確認能放得下第 3 個。
- **可達性測試**：照現有方式涵蓋新的打斷事件和查資料分支。

## 驗收
- 驗證器、可達性測試和 95 個單元測試都通過。
- 瀏覽器：三種小遊戲都能完成。360px 寬時程式碼行不會造成橫向捲動，太長就換行。
- 有倒數的時段，每張卡確實扣 5 分鐘。
- 「待審查」徽章有顯示。
- e2e 三個職業都能玩到結算畫面。

## HP7 決定
1. 三個小遊戲和印表機的內容照草稿。
2. Debug 放在「終於可以寫程式」；單元測試留在「測試環境出錯」（需上午選「只看重點檔案就核准」才出現），不一定每局都會遇到，可以。
3. 程式碼用**英文程式碼，每行附中文註解**，例如 `for (let i = 1; i < cart.length; i++)  // 從第 1 件開始加總`。註解只寫這行「想做什麼」，不點破錯誤；錯誤由翻開後的白話說明（`why`）解釋。計算總價改寫為：

```
1  function calcTotal(cart) {  // 計算購物車總價
2    let total = 0  // 總價從 0 開始
3    for (let i = 1; i < cart.length; i++)  // 從第 1 件開始加總
4      total += cart[i].price * cart[i].qty  // 加上單價乘以數量
5    if (coupon = "VIP") total = total * 0.9  // VIP 打九折
6    return total  // 回傳總價
```
   錯誤仍在第 3、5 行。Debug 線索卡中顯示程式碼的，也用英文程式碼加中文註解。
