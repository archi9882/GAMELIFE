# 提案：自由走動（草案，待 HP3 核准）

## 目的
讓玩家能自己在場景裡走：走到有「！」的地方，旁邊出現「處理：○○」按鈕，就開始那件事。強化「我在這個工作現場」的感覺；不想自己走的人，「帶我去」照常可用。

## 操作
| 方式 | 說明 |
|---|---|
| 點地板 | 角色自動找路走過去（繞過桌椅與牆） |
| 方向鍵（畫面左下，4 顆，各 ≥ 44px） | 按住持續走；放開停下。觸控時不會捲動頁面 |
| 鍵盤 | 方向鍵或 WASD（桌機） |
| 帶我去 | 保留，行為不變（給不想自己走、或用鍵盤報讀器的人） |

## 互動
- 角色走到某個地點附近（半徑約 1.5 格）且那裡有待辦，場景下方出現按鈕「處理：事件標題」；同地點有多件就列出多顆。按下等同於選這件事、而且已經到了，直接顯示事件。
- 走遠了按鈕就消失。「！」標記照舊，可以點。
- 已經選了某件事（例如按了清單）時，也可以自己走過去，到了就自動開始，不必再按「帶我去」。

## 規則
- **自由走動不額外花遊戲時間**：倒數只照既有規則（同群組換地點 +5 分鐘）。理由：手機上走路慢的人不該被懲罰。
- 只能走在地板上：每個場景定義「可走區域」與「家具障礙」，用格子（0.5 格）＋ A* 找路；水電工的天花板夾層只能用「帶我去」（要爬梯子）。
- 減少動態模式下照樣可以自己走（是玩家主動操作），只是鏡頭不平滑跟隨。

## 程式結構（不改劇本格式、不改引擎）
- `src/scene/nav.ts`：純函式（不依賴 three.js）——格子建立、A* 找路、碰撞滑動；有單元測試。
- 各場景 `SceneDef` 新增 `walkable`（矩形清單）與 `blocked`（家具矩形清單）。
- `kit.ts`：點地板（射線打到地面）→ 找路；方向鍵移動；`at(id)` 改為「角色在該地點半徑內且沒在走」；新增 `nearby(): string[]`（附近有哪些地點）。
- `app.ts`：顯示「處理：○○」按鈕；方向鍵 UI。

## 驗收
- 單元測試：找路會繞過障礙、走不到的點回傳最近可達點、方向鍵碰到牆會沿牆滑動不穿過。
- 瀏覽器：三個職業各從起點用「點地板」走到一個「！」地點並開始事件；方向鍵按住會移動、不捲動頁面；360px 寬沒有橫向捲動；「帶我去」流程照舊通過。

## 需要你決定（HP3）
1. 自由走動**不額外花遊戲時間**，可以嗎？
2. 操作同時提供**點地板＋方向鍵**，可以嗎？（只做其中一種可省約三成工）
3. 三個職業都做（水電工夾層只能用「帶我去」），還是先做老師、軟體工程師？
