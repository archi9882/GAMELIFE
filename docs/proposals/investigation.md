# 提案：查資料小遊戲（草案，待 HP1 核准）

## 目的
讓玩家做一次「專業判斷」：面對一堆資料，挑出跟問題有關的。重點是讓高中生看見「這份工作要先查對東西，才做得了決定」，不是考試。

## 玩法
1. 某些事件在顯示選項前，先出現「查資料」面板：一句任務說明＋ 4–6 張資料卡（只看得到標題）。
2. 點一張卡就打開它：顯示內容一行，並標示「有關 ✓」或「無關」。
3. 找齊所有「有關」的卡，才出現事件的選項。已打開的卡內容會留在卡片下方，作為做決定的依據。
4. **代價**：每打開一張卡花 5 分鐘遊戲時間（只在有倒數的群組才扣，與既有倒數規則一致）。所以從標題就能判斷的人，查得快；亂點的人，會讓同組其他事來不及。
5. 不另外扣精力或信任，避免「查資料」本身變成懲罰。

## 劇本格式（新增選填欄位，向下相容）
```ts
interface Investigation {
  prompt: string;            // 任務說明，≤ 40 字
  items: {
    id: string;
    label: string;           // 卡片標題，≤ 12 字
    detail: string;          // 打開後的內容，≤ 60 字
    relevant: boolean;
  }[];                       // 4–6 張；有關的 2–3 張
}
// GameEvent.investigate?: Investigation
```
驗證：張數、字數、有關張數、id 不重複；名詞折疊也會掃 `label`、`detail`。

## 引擎
- 狀態新增 `inspected: string[]`（`事件id:卡片id`）。
- `inspect(career, s, itemId)`：記錄、依規則扣時間；不能重複打開。
- `investigationDone(career, s, e)`：有關的卡都打開了才算完成；完成前 `choose` 會被擋下。
- 可達性測試：每個有查資料的事件，至少走「只開有關的」與「全部打開」兩種分支（影響倒數）。

## 首批內容（先做老師、軟體工程師）
| 職業 | 事件 | 任務 | 有關 | 無關 |
|---|---|---|---|---|
| 老師 | `t-parent-call` 家長來電（扣分不公平） | 先弄清楚扣分的原因 | 小晴的考卷、評分標準、這次小考全班分數分布 | 座位表、聯絡簿、出缺席紀錄 |
| 軟體工程師 | `s-alert` 線上告警（付款失敗） | 找出付款失敗從什麼時候開始、跟什麼有關 | 錯誤紀錄、今天的部署紀錄、付款服務的監控圖 | 辦公室 Wi-Fi 狀態、上週的需求文件、團隊行事曆 |

（卡片內容都是虛構情境，來源標「虛構」，對應公開描述的工作內容。）

## 需要你決定（HP1）
1. 打開一張卡扣 **5 分鐘**可以嗎？（太高會讓查資料的事件幾乎必定拖垮同組；太低就沒有判斷的意義）
2. 首批放在上面兩個事件可以嗎？注意兩者的差別：
   - 老師的「家長來電」在早上辦公室群組（時限 50 分），**會**扣時間。至少要開 3 張有關的卡＝15 分鐘，原本最省時也要 45 分，合計 60 分會超過時限。驗證器也要把「最少查資料時間」算進「做得完」，所以這組時限要從 **50 分調成 60 分**（調整後仍有事可能來不及）。
   - 軟體工程師的「線上告警」不在任何群組，**不會**扣時間，查資料只是判斷練習。
3. 水電工（待優化）這次先不做，可以嗎？
