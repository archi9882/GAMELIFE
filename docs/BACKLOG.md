## 備註
- 專業小遊戲（6、7）已討論決定：嵌進既有事件、不新增事件；只在有倒數的時段扣時間（同查資料），不新增時間分配類別，與真實資料對齊；內容依公開資料起草、審查代理檢查後先上線並標示「待審查」，等從業者看過再拿掉。軟體工程師已於 v0.10 參考從業者回饋並拿掉徽章；v0.10 的 ticket 主線新增了「寫單元測試」「主管 review 退回」「部署與上線」三件事件（HP9 決定）。
- 待辦 2～5 參考 Fab24hr 介紹文（aiposthub，2026-10-10）中提到的互動概念，只借概念，內容自行設計。
- 剩下一項會改動引擎與劇本格式，動工前先更新 `SPEC.md`，並維持「每個選項都有代價、無明顯正解」的原則。
- 倒數計時的設計目的是讓玩家看見「同時有很多事、不可能全部做好」的工作現實，不是製造壓迫感；時限太鬆（沒壓力）或太緊（做不完）都會被驗證器擋下。
- 名詞解釋與各職業內容仍待真實性審查（見 `research/`）。
- 真實資料進度：軟體工程師（Meyer 等 2021）與老師（TALIS 2018 Table I.2.29，臺灣高中職）已換成公開來源；水電工尚無公開時間分配資料，需訪談。
